# 코딩 규약 — 프로젝트 기본 가이드

목적
- 일관성 유지, 코드 품질 확보, 리뷰와 배포를 원활하게 하기 위함.

기본 규칙
- 파일 인코딩: UTF-8
- 줄 끝: LF
- 언어별 기존 설정 우선: 프로젝트에 ESLint/Prettier/clang-format 등 설정이 있으면 그 규칙을 따를 것.
- 기본 포맷(설정 없을 때의 권장값): 2-space indent, 최대 행 길이 100, 세미콜론 사용, 작은따옴표(') 우선, 트레일링 콤마(ES5) 허용.

브랜치 네이밍
- feature/짧은-설명
- fix/짧은-설명
- chore/짧은-설명
- hotfix/짧은-설명
- main(또는 master)은 보호 브랜치로 직접 푸시 금지

커밋 메시지
- Conventional Commits 권장: <type>(scope?): 한줄요약
  - 타입 예: feat, fix, docs, style, refactor, perf, test, chore, ci
  - 예: feat(auth): add refresh token handling
- 본문에는 왜 변경했는지, 중요 선택지나 부작용(breaking changes)이 있으면 명시

PR(풀 리퀘스트)
- 제목: 짧고 명확하게
- 본문: 변경 요약, 관련 이슈/배경, 테스트 방법(로컬 명령어 포함), 스크린샷(UI 변경시)
- 크기: 가능한 한 작고 의미 단위로 나눌 것
- 레이블/리뷰어 지정: 관련 팀/사람을 지정
- CI가 성공해야 병합

테스트
- 변경하는 기능에 대해 단위/통합 테스트 추가
- 테스트는 자동으로 실행되며, 로컬에서 `npm test`(또는 프로젝트 표준 명령)로 검증

코드 스타일 & 린팅
- 커밋 전 포맷터(예: prettier)와 린터(eslint)를 실행해서 경고/오류를 해결
- 자동 포맷: pre-commit 훅(설정되어 있으면) 사용 권장

보안 및 비밀정보
- 절대 시크릿(토큰, 비밀번호, 키)을 코드나 커밋에 포함 금지
- 환경변수 또는 시크릿 매니저 사용
- .gitignore에 민감 파일 추가

의존성 관리
- 의존성 업데이트는 PR로 진행
- 보안 업데이트는 우선 처리, `npm audit`(또는 해당 도구) 확인
- lockfile(package-lock.json / yarn.lock 등) 항상 커밋

문서화
- 중요한 변경은 README 또는 docs에 반영
- 사용법/설치/환경변수/마이그레이션 정보 포함

코드 리뷰
- 자기 PR을 먼저 셀프 리뷰
- 리뷰 요청 시 명확한 설명과 테스트 가이드를 제공
- 리뷰 코멘트에는 정중하고 구체적으로 답변

CI/CD
- PR에서 빌드/테스트 통과 확인 후 병합
- 배포 관련 변경은 관련 워크플로(예: GitHub Actions)를 업데이트

기타
- 지역화(i18n)가 필요한 문자열은 하드코딩 금지
- 접근성(ARIA 등)은 UI 변경시 고려
